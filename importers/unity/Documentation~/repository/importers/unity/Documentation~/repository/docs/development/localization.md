# Studio localization

The Studio-owned settings source, including themes, user and plugin settings, and translations, is an ordinary Devcel project at `devcel-studio/app-settings/studio.devcelproj.toml`, with tables under `Tables/`. Open it in Studio and edit/save it using the normal table UI.

`devcel-studio/src/app/i18n/generated/catalog.json` and `keys.ts` are Rust CLI outputs. Do not edit them directly. Import JSON is an interchange format, not the authoritative source.

The FormatJS Rust parser belongs to the optional `devcel-core` feature `localization`, enabled explicitly by `devcel-cli`. Studio starts from bundled generated assets and does not require the authoring database or generator. Cargo workspace feature unification may enable the CLI feature in a combined build; standalone Studio builds do not depend on it.

## Authoring tables

- **Messages:** `key` is a stable semantic dot key stored in a String cell, such as `common.save`, rather than a table/column data name. `source_message` is Japanese source text; `context`, `namespace`, and `usage_location` describe use. `source_revision` is the source UTF-8 SHA-256; `deprecated` retires a message.
- **Locales:** `code`, `display_name`, `fallback_locale` (a Reference to Locales), `direction` (`ltr`/`rtl`), `enabled`, and `required`. All shipped languages are enabled and required, including Basque (`eu`, Euskara) and Catalan (`ca`, Català). Japanese has no fallback; English falls back to Japanese. Basque and Catalan fall back to English, but their complete reviewed translations are required for release generation. Other fallback chains must ultimately reach Japanese.
- **Translation domains:** `Tables/Translations/<domain>.table.toml`, with data names `Translations_<domain>`. The domain is the first segment of the Messages key: `common.save` belongs to `Translations_common`, and `grid.addRow` to `Translations_grid`. Each domain table holds the locale rows for its messages, using `message_ref`, `locale_ref`, ICU `message`, `status` (`reviewed`, `draft`, `needs_review`), `reviewed_source_revision`, and `note`.

Reference cells store the referenced record UUID. The target table and display-column UUIDs live in the column's `reference_config`. Translation rows retain ordinary record UUIDs and review metadata; all domain tables reference the shared Messages and Locales tables. Validation checks domain ownership and duplicate message/locale pairs across the complete project.

To edit one message, find its key in Messages, open the translation table named by the first key segment, and choose the row with that message and the desired locale. Each table can be filtered and edited through the normal grid.

`devcel-core/build.rs` enumerates the files in `Tables/Translations/` and embeds them for the bundled settings seed when building localization support. Adding a domain requires no separate hard-coded file list.

Locale candidates come from the generated catalog, including supported right-to-left locales; do not maintain a separate hard-coded two-language list. `en-XA` is a development layout pseudo-locale, generated by expanding only English ICU literal nodes. Arguments, plural/select branches, and numeric/date formats are preserved. It is not a saved translation locale.

## Edit, save, validate, and generate

Run from the repository root; a built `devcel` binary may replace `cargo run -p devcel-cli --`.

```sh
cargo run -p devcel-cli -- --project devcel-studio/app-settings localization validate
cargo run -p devcel-cli -- --project devcel-studio/app-settings localization export \
  --out devcel-studio/src/app/i18n/generated
cargo run -p devcel-cli -- --project devcel-studio/app-settings localization export \
  --out devcel-studio/src/app/i18n/generated --check
```

1. Open the source project in Studio.
2. Edit the target translation, review it, set `status=reviewed`, and match `reviewed_source_revision` to `Messages.source_revision`.
3. Wait for saving before validation/export. The offline CLI cannot see unsaved editor changes.
4. Rebuild Studio and inspect affected screens, secondary windows, notifications, and errors in the relevant locales. Check `en-XA` for wrapping, clipping, and scrolling, and test direction-sensitive layouts with an RTL locale.
5. Run `--check` and commit the source database and generated outputs together.

### Changing source text

A mismatch between the source hash and `source_revision` blocks generation, preventing stale reviewed translations from shipping.

1. Edit and save `source_message`, then close Studio/serve sessions using this authoring project.
2. Run:

```sh
cargo run -p devcel-cli -- --project devcel-studio/app-settings localization reconcile
```

3. Reconcile updates the source hash and Japanese translation. Other affected translations become `needs_review`, retaining their prior reviewed revision.
4. Reopen the project, review translations, and update their status and reviewed revision.
5. Save, validate, and export. Export itself does not change the database.

For a new Messages row, fill in key, source text, and namespace; `source_revision` may remain `pending` until reconcile creates the hash and Japanese translation. Add required translation rows and their references/review metadata before generation.

## ICU MessageFormat

The official `formatjs_icu_messageformat_parser` parses ICU syntax. Use the version pinned by the workspace; do not introduce a separate placeholder parser.

| Form | Generated argument type |
|---|---|
| `{name}` | `string` |
| `{count, number}` or plural | `number` |
| `{date, date, short}` / `{date, time, short}` | `Date \| number` |
| `{kind, select, a {A} other {Other}}` | `string` |

Nested plural/select is supported and requires `other`. Every translation must match source argument names and types, though order and plural branches may differ. Mixing `{name}` and `{name, number}` for one argument fails. Use ICU apostrophe quoting for literal braces, such as `'{'`; `''` produces one apostrophe.

Messages are plain text. HTML/XML-looking text is not inserted as HTML, and no rich-text callbacks or `dangerouslySetInnerHTML` are used. Generated `MessageArgs` types detect missing and mistyped UI arguments.

## Initialization and bulk import

Never initialize over an existing source project.

```sh
cargo run -p devcel-cli -- localization init --dir /tmp/devcel-i18n --name studio
cargo run -p devcel-cli -- --project devcel-studio/app-settings localization import /tmp/messages.json
```

Import uses an array of objects with `key`, `ja`, `en`, `context`, and `usage`. Supply real Japanese source and reviewed English text. Import upserts while preserving message and existing translation UUIDs. Initialization creates the common domain; import creates additional domain tables as needed in the same validated save. Reconcile, validate, and export process every domain table with the existing commands. Changing `ja` without `en` retains the old English translation as `needs_review`; providing new English marks it reviewed against the new source revision.

Corrupt source/references, duplicate keys, invalid ICU, and reviewed-translation argument mismatches fail before writing. Import and reconcile are offline saved-database operations; close Studio/serve for the target source first.

## Validation and failure behavior

Generation validates tables, columns/types, required cells, Boolean/Select values, reference configurations, duplicate keys/locales/message-locale pairs/record UUIDs, missing references, fallback cycles, disabled fallbacks, and noncanonical locales. It checks coverage for every required locale for nondeprecated messages, reviewed state, source revisions, Japanese/source equality, nested ICU argument names/types, and unsafe keys/argument names.

Failure preserves existing catalogs and key definitions. Sorted output has a SHA-256 hash and does not depend on UUID or file enumeration order. Missing optional translations may use explicit fallback; required-language gaps cannot be hidden by fallback.

## Runtime settings and boundaries

User-local settings and live localization edits are owned by the ordinary [settings project](../manual/settings-and-plugins.md). View → Options opens its isolated editor. A complete valid settings revision atomically updates values, theme, and localization; invalid edits remain repairable in the source while the last valid runtime bundle remains active. Runtime local edits do not require release review hashes, but still obey structural/ICU safety and the application's required key/argument contract. Release generation retains the strict review gate.

Locale resolution uses an explicit supported selection, then a supported OS locale, then Japanese. OS locale is captured before UTF-8 initialization changes environment variables. Native and frontend locale candidates use the same generated catalog. Windows update text and native titles without remounting pages by locale, preserving drafts, focus, selection, and history. Revision checks prevent stale reads from overwriting newer notifications.

User table/column names, reference labels, Markdown, custom validation text/hints, and history comments are not translated. Locale number formatting does not change raw values, clipboard, or persistence. I64/U64 use BigInt to preserve display precision. Arbitrary DateTime strings are not guessed or reformatted; known application timestamps may be localized. Application-supplied file-dialog titles/filters are translated; OS-owned controls follow the OS language.

Rust/CLI/P2P/FFI/Tauri errors use explicit `AppError` variants (`code`, `text`, `input_validation`, `diagnostics`) on the error channel. Individual diagnostics are `{kind:"code",code,params}` or `{kind:"text",text}`, without parallel optional codes and messages. Free text remains text; never parse string prefixes or branch on translated messages. Display through `localizeError` as plain text.

## Plugins

Plugins may use String labels and metadata directly. `api.i18n` provides plugin-ID-scoped `registerMessages`, `getLocale`, `subscribe`, and `t`. Deactivation releases dictionaries and subscriptions. A plugin can provide an existing label as fallback for an invalid dictionary. Third-party metadata and custom UI are not automatically translated. Bundled plugins use application catalog messages and refresh extension labels after locale changes. Locale changes do not modify CSV data, explicit export formats, or user settings values.

## Check a localization change

Run `npm run assets:check` in `devcel-studio` after generating catalogs. Check the affected language in Studio, including interpolation and right-to-left layout when applicable. Commit the authoring tables and generated outputs together.

### Basque and Catalan

Basque (`eu`) and Catalan (`ca`) are complete left-to-right locales authored in the same per-domain translation tables as the other shipped languages. Both are required, so missing, unreviewed, or stale entries fail release validation rather than silently using English. Their self-names, Euskara and Català, appear in the locale catalog and the ordinary UserSettings language Select column. Regional OS locales such as `eu-ES`, `ca-ES`, and `ca-AD` resolve to these catalogs. Locale selection does not modify technical identifiers or file formats.

The localization runtime regression checks cover regional matching, switching from RTL to both languages, live updates without remounting or losing drafts, full key coverage, and all ICU branches. Before release, inspect both languages in the native app, including menus, Options, grid and column dialogs, warnings, and secondary windows.

## P2P error transport

P2P lifecycle failures use the same `AppError` envelope as other commands. The local Rust `P2PManager` initialization, open, promotion and disconnect APIs return `AppError`; `P2PError::into_app_error` preserves semantic code/parameter causes and places opaque transport/OS/parser details under a localized summary. Do not use `Display`, `to_string()`, or English-prefix matching at the presentation boundary.

The native events use structured error fields: `p2p-error.message`, `p2p-state-changed.error` (only for `failed`), and `p2p-disconnected.reason` contain `AppError`, not strings. Frontend listeners keep these objects until `localizeError` renders them, so changing the language also updates an existing notification. Disabled-command detection checks `error.commandNotFound` and the literal `get_p2p_status` command parameter, independent of UI language.

The local `DevcelClient` and `DevcelServer` error returns and in-process pending-response channels also carry `AppError`; remote error envelopes survive ping, forwarding, and snapshot-application failures without stringification. OS/parser details remain literal parameters under localized summaries. Formatting remains only at intentional terminal CLI/C boundaries. Incoming-operation policy checks emit `p2p.validation.*` codes for denied operations, batch-size violations, UTF-8 byte-limit violations and invalid separators.

Focused coverage: core `p2p_errors::localization_tests`, `msgpack_client::localization_tests` and `msgpack_server::localization_tests`, native `p2p_event_listener::localization_tests` (with the `p2p` feature), and `node scripts/check-p2p-errors.mjs` from `devcel-studio`. These tests exercise typed transport and production React/localization without opening network sockets; they do not replace end-to-end network tests.

## Settings choice sources

Theme and display-language candidates come from the validated Themes and enabled Locales records. The corresponding UserSettings Select configurations declare only the `system` mode; they do not duplicate the candidate IDs. The compiler validates selected and default IDs against the source records. The settings editor subscribes to the published catalog for candidates and labels, so adding a theme or locale does not require editing a second option list. Normal project Select columns retain their authored options.

Themes contain one record per theme, including its stable key, label reference, explicit light/dark appearance and typed Color32 columns. The `system` choice is a mode, not a theme record. Missing selected IDs invalidate the proposed settings snapshot; the last valid snapshot is retained rather than silently choosing a different theme or language.
